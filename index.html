Before computers, libraries used this.

A card catalog was a physical database. Every book got an index card: title, author, genre, shelf location. Rows and columns, just made of paper. A relational database does the exact same job — it just keeps millions of "cards" in tables, and lets you ask questions about them in seconds instead of hours.

Four words you need before anything else

Table
A drawer of the catalog. One subject, e.g. books, one drawer.
Row
One index card. A single book, a single borrower, a single event.
Column
One line on every card, always in the same spot — like "Author:" always written second.
Data type
What kind of value a column holds — text, a whole number, a date. SQL enforces it so a "year" can't accidentally hold a name.

The only sentence you need today

Every query you write in this module has the same shape:

SELECT columns FROM table;

SELECT says which columns you want to see. FROM says which drawer to pull them from. That's it — that's the whole sentence. Everything else in SQL is a variation on this.

Try these, one at a time

  • SELECT * FROM borrowers; — every column, every row
  • SELECT title, author FROM books; — only the columns you name
  • SELECT DISTINCT genre FROM books; — each unique value once
  • SELECT * FROM books LIMIT 5; — cap how many rows come back
  • SELECT name AS Member FROM borrowers; — rename a column in the output with AS
