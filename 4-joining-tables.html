Why Data Is Split Across Tables

Databases normalize data into multiple tables to avoid duplication and keep data consistent. Instead of repeating a customer's name on every order row, we store customers once in a customers table and reference them by ID from an orders table.

Primary & Foreign Keys

TermDefinitionExample
Primary Key (PK)Uniquely identifies each row in its own tablecustomers.customer_id
Foreign Key (FK)A column referencing a primary key in another table, creating a relationshiporders.customer_id → customers.customer_id

Rule of thumb: FK values must exist in the referenced table's PK (or be NULL)

INNER JOIN

Returns only rows where there's a match in both tables. If a customer has no orders, they won't appear.

SELECT c.name, o.order_id, o.amount
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id;

LEFT JOIN

Returns all rows from the left table, plus matching rows from the right table. When there's no match, the right table's columns come back as NULL — this is the key to finding "missing" relationships (e.g., customers with no orders).

SELECT c.name, o.order_id, o.amount
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id;

If o.order_id IS NULL → that customer has never ordered

INNER vs LEFT JOIN

Join TypeIncludes unmatched left rows?Typical use
INNER JOINNoOnly rows that exist in both tables (e.g., orders with valid customers)
LEFT JOINYes (with NULLs for missing right side)Finding gaps — customers with no orders, products never sold

Putting it all together

SELECT c.name, o.order_id, p.product_name, p.category
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
LEFT JOIN products p ON o.product_id = p.product_id
WHERE o.order_id IS NULL;
-- Customers who have never placed an order

🎯 Practice Challenge 1: Cross-Table Question

Task: List each order with the customer's name, country, and the product name and category (combine all three tables).


Show solution 
SELECT o.order_id, c.name AS customer_name, c.country,
       p.product_name, p.category, o.amount, o.order_date
FROM orders o
INNER JOIN customers c ON o.customer_id = c.customer_id
INNER JOIN products p ON o.product_id = p.product_id
ORDER BY o.order_date DESC;

🎯 Practice Challenge 2: Products Never Ordered

Show solution

  • No matching order at all (order_id IS NULL), or
